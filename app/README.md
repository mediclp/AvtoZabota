# АвтоЗабота — мобильное приложение (Flutter)

Каркас MVP на стандартных компонентах Material. Вся логика уже работает, внешний вид временный: экраны переделываются под макеты дизайнера, а логика при этом не меняется.

Логика — это перенос Python-прототипа (`../avtozabota`) один к одному, с теми же тестами и цифрами. Справочники (`assets/data/*.json`) общие: их читают и приложение, и прототип.

## Запуск

Flutter 3.50 установлен в `E:\dev\flutter`, Git — в `E:\dev\git`, оба добавлены в PATH пользователя. В **новом** окне терминала, из папки `app`:

```bash
flutter pub get
flutter test
flutter run -d chrome
```

- `flutter pub get` — скачать пакеты.
- `flutter test` — 62 теста логики и экранов.
- `flutter run -d chrome` — открыть приложение в браузере. Клавиша `r` в терминале перезагружает изменения кода на лету.

**Место на диске.** Пакеты по умолчанию кэшируются на диск C:, а на нём мало места. Чтобы кэш лежал на E:, один раз выполните в PowerShell:
```powershell
[Environment]::SetEnvironmentVariable('PUB_CACHE', 'E:\dev\pub-cache', 'User')
```

**Android.** Нужны Android Studio и Android SDK. Путь к проекту содержит кириллицу, а Gradle (сборщик Android) на Windows с этим иногда не справляется. Если сборка под Android упадёт с ошибкой про non-ASCII путь, скопируйте проект в папку с латинским путём, например `E:\dev\avtozabota_app`.

**Material — отдельный пакет.** С Flutter 3.47 компоненты Material и Cupertino вынесены в пакеты `material_ui` и `cupertino_ui`. Поэтому в коде `import 'package:material_ui/material_ui.dart'`, а не старый `package:flutter/material.dart`, который помечен устаревшим. Примеры в интернете в основном со старым импортом: остальной код в них тот же, меняется только эта строка.

## Устройство

```
lib/
  core/          чистая логика без Flutter — её проверяют тесты
    models.dart      данные: машина, запись ТО, регламент, результат расчёта
    schedule.dart    график ТО: сроки по пробегу и времени, напоминания
    regulations.dart справочник регламентов
    tires.dart       сезонная смена шин (календарь + погода + закон)
    weather.dart     правило «пора менять шины» по температуре
    cities.dart      города, климатическая зона по координатам
    format.dart      даты, километры, тексты для экранов и уведомлений
    notification_plan.dart  какие уведомления и когда показать
  data/
    api.dart           запросы в интернет (Open-Meteo: прогноз и поиск города)
    store.dart         AppStore: машины, сохранение на телефоне, кэш прогноза, настройки уведомлений
    notifications.dart отправка уведомлений (flutter_local_notifications)
  ui/            экраны
    cars_screen.dart        список машин
    add_car_screen.dart     добавление машины
    city_picker_screen.dart выбор города
    car_screen.dart         график ТО машины, обновить пробег, удалить
    service_screen.dart     «Отметить ТО»
    history_screen.dart     история обслуживания
    reminders_screen.dart   уведомления: включить, время, тест; ближайшие напоминания
    widgets.dart            общие мелочи: цвет статуса, поле для числа
  main.dart      запуск: загрузить данные → показать список машин
assets/data/     regulations.json, cities.json
test/            core_test.dart (логика), app_test.dart (экраны)
```

**Как данные доходят до экрана.** `AppStore` наследует `ChangeNotifier`. Экраны обёрнуты в `ListenableBuilder(listenable: store, ...)`. Любое изменение (`addCar`, `addService`, `addReading`) сохраняет данные и вызывает `notifyListeners()`, после чего экраны перерисовываются сами. Отдельный пакет для управления состоянием не нужен.

**Хранение.** Список машин хранится одной JSON-строкой в `SharedPreferences`; для этого у классов есть `toJson` / `fromJson`. Прогноз погоды кэшируется так же: один раз в день на каждый город.

**Слои не перемешаны.** `core` ничего не знает о Flutter, интернете и хранении: ему передают данные, он возвращает результат. Поэтому логику проверяют обычные быстрые тесты, и её можно менять, не трогая экраны.

## Уведомления

Пакет `flutter_local_notifications` 23.

- **Что приходит.** Напоминания за 7 и за 1 день до срока, в выбранное время (по умолчанию 10:00). Включаются на экране «Напоминания» (значок колокольчика); там же выбирается время и отправляется тестовое уведомление. Разрешение спрашивается только в момент включения.
- **Как устроено.** `core/notification_plan.dart` строит план: что и когда показать. Это чистая логика, она покрыта тестами. `data/notifications.dart` (`LocalNotifier`) передаёт план системе. После **любого** изменения данных `AppStore` отменяет все отложенные уведомления и ставит заново — так не нужно отслеживать, что именно поменялось.
- **Тонкости:**
  - iOS хранит не больше 64 отложенных уведомлений, поэтому ставятся ближайшие 50;
  - если напоминание на сегодня, а время уже прошло (например, похолодало днём), оно придёт через минуту, но один раз и не позже 21:00;
  - время неточное (`inexactAllowWhileIdle`, ± несколько минут): для этого не нужно особое разрешение Android на «точные будильники».
- **Платформы.** Android и iOS — по расписанию. В браузере только тестовое уведомление: отложенные уведомления пакет в вебе не поддерживает.
- **Настройка платформ уже сделана:**
  - Android: `compileSdk = 37`, desugaring в `android/app/build.gradle.kts`, приёмники и `RECEIVE_BOOT_COMPLETED` в `AndroidManifest.xml` (после перезагрузки телефона уведомления восстанавливаются);
  - iOS: делегат в `ios/Runner/AppDelegate.swift`.
- **Не проверено на устройстве.** Android SDK и телефона в разработке не было; логика и экран проверены тестами и в браузере.
