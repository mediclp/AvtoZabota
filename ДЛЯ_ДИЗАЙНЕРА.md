# АвтоЗабота: инструкция для дизайнера

Приложение уже работает: оно считает сроки ТО, хранит машины, присылает напоминания. Но выглядит оно пока «по умолчанию»: стандартные компоненты Material, синий цвет, без иконок и иллюстраций. Твоя задача — сделать дизайн и перенести его в приложение.

Логику трогать не нужно: она отделена от экранов и покрыта тестами. Меняются только файлы экранов и тема.

---

## 1. Как запустить проект (через Claude Code)

Проще всего делать всё в **Claude Code** (приложение Claude, вкладка Code). Он сам выполнит команды, а ты будешь видеть результат.

1. Открой Claude Code и выбери пустую папку для проекта, например `D:\Projects`. Путь лучше без кириллицы и пробелов.
2. Напиши Claude:
   > Склонируй репозиторий https://github.com/ВЛАДЕЛЕЦ/avtozabota в эту папку и перейди в него. Прочитай CLAUDE.md и ДЛЯ_ДИЗАЙНЕРА.md.

   Ссылку на репозиторий даст Илья.
3. Потом:
   > Установи Flutter, если его нет, и запусти приложение в Chrome.

   Claude скачает Flutter (около 2 ГБ) и запустит `flutter run -d chrome`. Откроется Chrome с приложением.
4. Пока приложение запущено, правки в коде подхватываются на лету: Claude нажмёт `r` в терминале, или нажми сама/сам.

**Если GitHub или пакеты не скачиваются** («Could not connect», «authorization failed»), значит, нужен VPN. Скажи Claude:
> Сеть не пускает на github.com и pub.dev. У меня VPN на порту NNNN — настрой прокси для git и flutter.

### Без Claude Code (вручную)

Если хочется самостоятельно:
1. Установить Flutter: https://docs.flutter.dev/get-started/install
2. Из папки `app`:
   ```bash
   flutter pub get
   flutter run -d chrome
   ```

## 2. Что где лежит

```
app/                    ← приложение (Flutter, язык Dart)
  lib/
    main.dart           ← ТЕМА (цвета, шрифты) — меняй
    ui/                 ← ЭКРАНЫ — меняй
    core/               ← логика расчёта — не трогать
    data/               ← хранение, интернет, уведомления — не трогать
  assets/
    data/               ← справочники (регламенты, города) — не трогать
                          сюда же можно добавить свои картинки и шрифты (в новую папку)
  test/                 ← тесты: после правок запускаются, чтобы ничего не сломалось
avtozabota/             ← Python-прототип логики — для дизайна не нужен
```

**Правило:** меняешь `lib/ui/`, `lib/main.dart` и при необходимости добавляешь картинки и шрифты в `assets/`. Остальное — не твоя зона. Если для дизайна нужны данные, которых нет (например, «сколько потрачено за год»), попроси Илью, а не дописывай логику в экран.

## 3. Экраны и данные на них

Ниже — какие данные есть на каждом экране. Можно показывать их как угодно, но придумывать данные, которых нет, не получится.

### Список машин — `lib/ui/cars_screen.dart`
- Для каждой машины: марка, модель, год, текущий пробег, **самый срочный пункт** (название и статус).
- Пустое состояние: «Добавьте машину» и кнопка.
- Кнопки: «Добавить авто», колокольчик → экран «Напоминания».

### Добавление машины — `lib/ui/add_car_screen.dart`
Поля (почти все обязательные):
- **Машина:** марка и модель из списка (18 моделей) или «другая» (тогда ввод текстом); год выпуска; двигатель — только у Kia Sportage и Toyota RAV4, с вариантом «Не знаю».
- **Пробег и последнее ТО:** пробег сейчас; дата последнего ТО; пробег на последнем ТО; пробег за месяц (необязательно).
- **Город:** отдельный экран поиска. По городу приложение берёт прогноз погоды и климатическую зону.
- **Шины:** «Лето + зима» / «Всесезонные» / «Не знаю». Если сезонные — какие стоят сейчас и есть ли шипы.

Форма длинная. Хороший кандидат на пошаговый мастер (2–4 шага): это на твоё усмотрение.

### Выбор города — `lib/ui/city_picker_screen.dart`
- Поиск по встроенному списку из 76 городов (работает без интернета).
- Кнопка «Искать другой населённый пункт онлайн».
- У каждого результата: название, регион, климатическая зона.

### График ТО машины — `lib/ui/car_screen.dart`
Главный экран приложения.
- **Шапка:** год, двигатель, пробег, средний пробег в день и откуда он взят, откуда срок по шинам (прогноз погоды или календарь).
- **Список пунктов графика** — по одному на расходник: масло, воздушный фильтр, салонный фильтр, колодки, тормозная жидкость, свечи и шины. Отсортированы от срочных к спокойным. У каждого пункта есть:
  - **статус** — один из четырёх: `Просрочено` / `Скоро` / `В норме` / `Нет данных`. Сейчас это красный, оранжевый, зелёный и серый;
  - **срок** — дата и «через N дней»;
  - **причина срока** — «по пробегу», «по времени» или «по прогнозу погоды»;
  - **сколько осталось километров** (или «пробег превышен на …»);
  - **у шин:** какие ставить, окно смены, срок по закону (1 декабря / 1 июня).
- **Кнопки:** «Пробег» (обновить текущий), «Отметить ТО», «История», «Удалить машину». Нажатие на пункт открывает «Отметить ТО» с уже отмеченным пунктом.

### Отметить ТО — `lib/ui/service_screen.dart`
- Поля: дата, пробег, галочки «что сделали» (расходники), для шин — какие поставили, стоимость, комментарий.
- Место под **фото чека** зарезервировано. Функции пока нет, но в дизайне её стоит предусмотреть.

### История — `lib/ui/history_screen.dart`
- Записи от новых к старым: дата, пробег, что сделали, стоимость, комментарий. Отдельно помечены записи, введённые при добавлении машины.
- Сумма всех расходов.

### Напоминания — `lib/ui/reminders_screen.dart`
- Переключатель «Уведомления на телефоне», время уведомлений, «Отправить тестовое».
- Список ближайших напоминаний за 2 месяца по всем машинам.

### Общие элементы — `lib/ui/widgets.dart`
- Цвет и иконка для каждого статуса, плашка статуса (`StatusChip`), поле ввода числа.
- **Цвета статусов меняются здесь, в одном месте.**

### Тексты
Тексты на экранах собираются в `lib/core/format.dart` («до 10.12.2026 (через 28 дн., по пробегу) · осталось 3 600 км»). Если нужен другой формат или текст для дизайна разобьётся на части (например, крупно «28 дней», мелко дата), скажи Илье или попроси Claude добавить отдельную функцию — в `core` правки нужно согласовывать.

## 4. Как переносить дизайн в код

Удобнее всего просить Claude Code по одному экрану:

> Вот макет экрана графика ТО (прикрепляю картинку). Переделай `lib/ui/car_screen.dart` под него. Логику и данные не меняй — только внешний вид. Запусти тесты.

> Поменяй тему приложения в `lib/main.dart`: основной цвет #2E7D32, шрифт Inter (добавь его в assets), скругления карточек 16.

> Сделай плашку статуса в `lib/ui/widgets.dart` как на макете: цветная точка и текст, без рамки.

После правок Claude должен запустить проверки (они записаны в CLAUDE.md):
```bash
cd app
flutter analyze
flutter test
```
Если тест упал из-за **текста** (например, тест ищет надпись «Скоро», а ты её переименовал), это нормально: попроси Claude поправить тест под новый текст. Если упал тест логики (`core_test.dart`), значит, затронуто не то — откатить.

**Цвета и шрифты** лучше задавать один раз в теме (`ThemeData` в `main.dart`), а не в каждом экране. Тогда тёмная тема и смена цвета работают сразу везде.

**Внимание:** в Flutter 3.47+ Material подключается так: `import 'package:material_ui/material_ui.dart';`. В интернете почти все примеры со старым `package:flutter/material.dart`. Код в них тот же, меняется только эта строка.

## 5. Работа с GitHub

Чтобы не мешать друг другу:
1. Перед началом: «Подтяни последние изменения из GitHub».
2. Работай в отдельной ветке: «Создай ветку `design/car-screen`».
3. Когда экран готов: «Закоммить и запушь, открой pull request». Илья посмотрит и смержит.

Ничего страшного, если что-то сломается: в Git всё можно откатить.
